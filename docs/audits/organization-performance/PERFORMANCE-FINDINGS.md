# Constats — Rendement

| ID | Sévérité | Statut | Constat | Preuve | Risque / correction attendue |
|---|---|---|---|---|---|
| PERF-01 | Élevée | REPRODUIT | Les entrées d’un `User.isActive=false` restent dans les agrégats opérationnels et financiers. | Désactivation canonique : ancienne session refusée (401), mais 8 h et 640 CAD demeurent; réactivation sans restauration de session. | La conservation historique peut être légitime, mais elle est silencieuse. Faire approuver la règle et libeller/filtrer explicitement l’historique. |
| PERF-02 | Élevée | IDENTIFIÉ_STATIQUEMENT | Les projets archivés/inactifs ne sont pas distingués dans les agrégats. | Les requêtes ne filtrent ni `Project.status` ni l’état métier du mandat; aucun parcours archivé n’a été muté pour cette campagne. | Le portefeuille actuel peut inclure du travail historique sans indication. Ajouter un état/périmètre explicite, sans supprimer l’historique. |
| PERF-03 | Moyenne | CONFIRMÉ | Les deux projections chargent toutes les entrées/mandats sans pagination ni plafond. | `findMany` sans `take`, curseur ou agrégation SQL. | Temps de réponse et mémoire croissent avec l’historique; implémenter pagination/agrégats serveur et tests volumétriques. |
| PERF-04 | Moyenne | CONFIRMÉ | Le filtre financier `userId` sélectionne des mandats, puis calcule leur coût avec toutes les entrées, pas seulement celles de l’utilisateur. | Filtre `projectTasks.some(timeEntries.some(userId))`, puis `flatMap` sans filtre utilisateur. | Le nom du filtre peut faire croire à une rentabilité individuelle. Renommer « mandats auxquels participe » ou formaliser une vue individuelle distincte. |
| PERF-05 | Moyenne | CONFIRMÉ | `asOf` n’est pas une photographie financière historique complète. | Il limite les heures, mais lit le montant vendu et les taux dans leur état courant. | Une consultation rétrospective peut évoluer. Documenter la sémantique ou construire une projection temporelle gouvernée. |
| PERF-06 | Moyenne | CONFIRMÉ | L’écran financier n’expose aucun des filtres API `view`, période, conseiller, devise ou `asOf`. | Appel fixe `{ view: "cumulative" }`. | Les contrôles attendus sont inaccessibles dans l’interface. Ajouter les filtres après validation produit de leur sémantique. |
| PERF-07 | Moyenne | REPRODUIT | Le menu et la page sont ouverts à tout rôle `ADMIN`, alors que l’API exige `FINANCIAL_RENDEMENT_READ`; un ADMIN client obtient un message générique. | Chrome authentifié : page visible puis message d’erreur générique; API 403, aucune donnée. | Parcours trompeur, sans fuite financière. Piloter la navigation par capacité et afficher un refus explicite. |
| PERF-08 | Moyenne | CONFIRMÉ | Un changement de période ne remet pas `loading` à vrai et laisse l’ancien état en mémoire pendant la requête. | `setLoading(true)` absent dans l’effet après le premier chargement. | Risque de données visuellement périmées pendant le chargement; ajouter état de rechargement et tests de réponses désordonnées. |
| PERF-09 | Faible | CONFIRMÉ | Les raisons d’incomplétude sont affichées comme codes techniques anglais. | `incompleteReasons.join(", ")`. | Faible intelligibilité commerciale; mapper vers des libellés FR/EN accessibles. |
| PERF-10 | Moyenne | CONFIRMÉ | Une ancienne méthode financière non gouvernée demeure dans `MandateService`, bien qu’inutilisée. | `MandateService.getRendement` calcule sur `Float`, `montantVendu` et `tauxHoraire`; aucune référence d’appel actuelle. | Risque de réactivation accidentelle. Supprimer après preuve d’absence de consommateur ou verrouiller par test d’architecture. |
| PERF-11 | Information | PASS | `TimelogEntry` n’est pas additionné à Rendement. | Fixture API croisée : 99 h Timelog et 8 h TaskTime donnent 8 h Rendement. | Conserver la documentation explicite de cette séparation. |
| PERF-12 | Information | PASS | L’isolation organisationnelle et l’autorité financière sont appliquées côté serveur. | Prédicat parent `Project.organizationId`; permission plateforme avant lecture financière; campagne API réelle. | Maintenir ces contrôles comme invariants. |

Aucun constat de cet audit n’a été corrigé dans le produit, conformément au mandat d’audit ciblé.
